**`PreviewGenerator` 인터페이스**: `TaskService`는 "Preview를 만들어 달라"고만 요청하고 누가 만드는지는 모른다. 지금은 Mock, 이후 AnyDoor 구현체로 바꾼다. 단, AnyDoor처럼 오래 걸려 비동기 처리가 필요해지면 API와 화면 흐름도 바뀔 수 있다.

## 직접 테스트하며 찾은 문제

1. **공유를 눌렀는데 새로고침하면 "작업 중"으로 돌아감** — DP Plan만 Week 1의 화면 안 임시 처리가 남아 있던 과도기 상태. 상태 규칙을 서버로 옮김 (PR #2, D13)
2. **새 코드인데 같은 증상** — 오류 알림 없이 돌아가는 걸 보고 "예전 코드가 돌고 있다"고 추론. 브랜치를 Fetch하지 않은 것이 원인. → 코드를 고치기 전에 **지금 실행 중인 코드가 무엇인지**부터 확인
3. **예시 작업만 "채택한 Preview가 있어야" 오류** — 새 규칙 이전에 만들어진 데이터가 규칙을 만족하지 못함 (데이터 마이그레이션 문제). Prototype이라 DB 재생성으로 해결

## 오후 — 외부 검토 반영과 사용자 제안 (PR #3~#6)

- **외부 AI 검토를 코드와 대조 (PR #3)** — ChatGPT 검토 의견을 Claude가 실제 코드와 대조해 수용 / 반박 / 보류로 나눔. 그 과정에서 검토가 직접 지적하지 않은 버그 발견: 검토 완료 후 영역을 바꾸면 **채택하지 않은 안이 매장에 공유될 수 있었다** → 수정 (D14)
- **공유 후 수정 불가 (PR #4)** — 직접 써 보며 "오타 하나도 못 고친다"는 불편 발견. 문제를 "잠금"이 아니라 "다시 여는 길이 없음"으로 재정의 → 공유 취소 후 수정 (D16)
- **공유 후 다음 행동 부재 (PR #5)** — 사용자 제안. "✓ 공유됨 + \[← 대시보드로\]", 직원 화면 로고 링크 제거 (D17)
- **한 방향 크기 조절 (PR #6)** — 사용자 제안. 변 가운데 핸들 추가
- 여러 상품 동시 교체는 AnyDoor 실험 후 판단하기로 **보류** (D18)
