# 2026-11-10 실제 사진 재확인 R1·R2·R2b · 입력 가이드 변경 (D30)

## Problem

11/9 P01~P04는 생성 인물(Higgsfield GPT Image 2.6)로 한 실험이라, 실제 사진에서도 같은 결과가 나오는지 확인하지 않고는 입력 가이드를 확정할 수 없었다.

## Context

- 사용자가 본인 실제 사진 2장을 촬영(회색 반팔 포켓 티, 1932×2576): R1 상반신, R2 전신
- 조건은 P01·P02와 동일하게 고정: strength 1.0 / steps 30 / scale 4.5 / shape_control false / ref_refine true / fp16, seed 42·7·123, 상품 `red_tee.jpg`
- 실제 사진은 개인 얼굴이 나오므로 저장소에 올리지 않고 학교 PC 실험 폴더에만 둔다

## AI 활용 목적 / Proposal

- Claude: 영역 좌표 작성, 실행 스크립트(`run_R1.bat`, `run_R2b.bat`) 작성, 결과 확대 비교와 1차 판정, R2 실패 원인 가설과 보완 실험(R2b) 제안, 가이드 문구 초안
- 실행(.bat 더블클릭)은 사용자

## 발견

1. **원래 입은 옷은 문제가 되지 않았다.** 회색 → 빨강 9/9, 원본 가슴 포켓 9/9 사라짐
2. **11/9의 팔 이상(seed 42 흉터·문신 무늬)은 실제 사진에서 재현되지 않았다.** 생성 이미지 쪽 특성이었을 가능성
3. **영역 위쪽이 목 피부에 걸치면 턱 아래에 경계선이 생긴다** (R2). 다시 그려지는 범위가 지정 영역보다 약간 넓다. 원인은 Claude가 영역을 목선보다 조금 위로 잡은 입력 위치였고, 목선으로 내리자(R2b) 턱 경계선은 3/3 사라졌다. 목선에 맞춰도 원본 회색 깃은 남지 않았다
4. **전신이 상반신보다 불안정하다.** R1은 목 부분 3/3 깨끗, 전신은 영역을 고친 뒤에도 2/3
5. 핏은 생성 인물과 마찬가지로 상품 사진 모양을 따라 박시해진다
6. **서비스는 seed 42 고정**이다 (`AnyDoorPreviewGenerator`가 AI 서버 기본값 사용, 다시 생성 버튼 없음). 시연에 나오는 결과는 seed 42 한 장이며, R1 seed 42는 통과

## User Decision → Implementation (D30)

사용자가 판정과 문구 확정 후 반영 승인. 새 기능 없이 화면 문구만 변경했다.

- 등록 화면: 용도를 "직원·모델이 상품을 입은 모습 미리 보기"로, 인물 사진은 정면·팔 내린 자세·**상반신 권장**, 원래 옷의 색·포켓·소매 길이는 상관없음. 마네킹 촬영 안내는 D28 이후 범위가 아니라서 삭제
- 영역 지정 화면: 목선~밑단·소매 끝까지(P03), 위쪽은 옷의 목선에 맞춤(R2·R2b), 핏은 상품 모양을 따라감(한계 안내)
- "다시 생성"(seed 변경)은 이번 주 "새 기능 없음" 원칙에 따라 넣지 않음 → 회의 후 판단
