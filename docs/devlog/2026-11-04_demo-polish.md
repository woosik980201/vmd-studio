# 2026-11-04 | 시연 준비 — 삭제 기능 · 화면 정리

## Problem

3차 미팅(11/6) 시연을 준비하며 실제로 화면을 돌려 보니, 테스트 작업이 대시보드에 쌓여도 지울 방법이 없었다.
화면 전체를 점검한 결과 시연 때 눈에 띄거나 서비스의 약속과 어긋나는 부분도 나왔다.

## Context

- 사용자: 녹화 중 "데이터를 삭제할 수 있는 기능이 필요하다", 대시보드 하단 문구가 무엇인지 질문
- 사용자 판단: 녹화는 11/5로 미루고 디테일 점검을 먼저 진행

## AI 활용

Claude가 화면 코드와 실제 페이지를 점검해 문제 목록과 우선순위를 제시했다. 사용자가 목록을 보고 일괄 수정을 승인했다.

## 발견과 수정 (D26)

| 문제 | 수정 |
| --- | --- |
| 공유하지 않은 작업도 `mode=view`로 열면 "확정된 DP Plan"으로 표시 | 공유 전이면 "아직 공유되지 않은 DP Plan입니다"만 표시 |
| 작업 삭제 불가, 빈 목록 안내 없음 | `DELETE /api/tasks/{id}`, 대시보드 삭제 버튼·확인 창, 빈 목록 안내 |
| 대시보드 하단 `Week 2 Prototype` 문구 | 삭제 |
| 버튼은 "작성 완료"인데 상태는 "검토 완료" | 화면 이름을 "작성 완료"로 통일 (내부 값 `REVIEWED` 유지) |
| 화면에 `Prototype`, `보기 상태 미리보기` 표현 | "직원 화면 미리보기"로 변경 |
| `Dashboard`와 `대시보드` 혼용 | 버튼을 `대시보드로`로 통일 |

## 확인 중 발견한 문제

병합 후 브라우저에 새 HTML과 예전 JS가 섞여 삭제 버튼이 보이지 않았다. 서버 응답에 `Cache-Control`이 없어 브라우저가 파일을 재사용한 것이 원인이다. 사용자가 강력 새로고침으로 삭제 버튼을 확인했고, 재발을 막도록 화면 파일에 `no-cache`를 적용했다.

## 디자인 변경 (D27)

사용자가 "밋밋하다", "글씨체가 슬림하다"고 판단하고 패션·스튜디오 사이트 레퍼런스를 제시했다. Claude가 시안을 여러 개 만들었고, 추천한 시안 3(행택, 조명)은 실제 화면에서 사용자가 "구리다"고 판단해 폐기했다. 최종안은 크림색 바탕, 굵은 대문자 제목, Higgsfield로 만든 흑백 마네킹 표지다.

## 남은 한계

- 직원 화면 차단은 화면에서만 한다. 로그인·권한이 없어 API는 여전히 작업 내용을 돌려준다
- 삭제는 현재 Preview만 지운다. 재생성으로 쌓인 이전 Preview 파일은 `uploads/`에 남는다
- 작업을 모두 지운 뒤 서버를 다시 켜면 예시 작업 3개가 다시 들어간다
- 휴대폰 화면 대응(직원 화면)은 회의 후 검토
