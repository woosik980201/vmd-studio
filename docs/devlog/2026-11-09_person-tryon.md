# 2026-11-09 | 사용자 결정(D29) · 인물 착용 실험 P01~P04

## Problem

D28(11/6)에서 적용 범위를 "실제 사람에게 의류를 입혀 합성"으로 좁혔다. 이에 따라 두 가지를 정해야 했다.

1. 서비스의 사용자를 VMD로 둘지, 고객으로 바꿀지
2. AnyDoor가 사람에게 옷을 입히는 것을 어디까지 할 수 있는지

## Context

- 금요일(11/13)에 회의가 있고, 이 회의까지 완성하는 것이 목표다. 다음 주 발표는 팀원 중 완성도가 가장 높은 프로젝트로 준비할 예정이다
- 그래서 이번 주 원칙을 "이미 동작하는 것은 깨지 않는다"와 "화면 수정은 문구·가이드까지"로 정했다
- 마네킹 가까운 구도에서 팔이 피부색으로 바뀐 전례가 있다(D24)

## 사용자 결정: D29

- AI 제안: A(VMD 유지, 직원·모델이 입은 모습으로 스타일링 확인)와 B(고객 전환, 퍼스널컬러처럼 내 몸에 대 보기)의 변경 범위·일정·스토리 연결을 비교하고 A를 권함
- **사용자 결정: A**
- 이유: 남은 기간 안에 완성 가능, 검증된 흐름(영역 지정 → 생성 → 채택 → DP Plan → 직원 공유) 재사용, "VMD가 판단하고 AI는 Preview" 원칙 유지
- 남은 확인: 교수님이 예로 드신 "퍼스널컬러처럼 내 몸에 대 보기"는 고객 관점에 가깝다. 회의에서 A로 정한 이유를 설명하고 피드백을 받는다

## 실험 준비: 생성 인물 이미지

- **사용자 제안:** 학교에서 촬영이 어려워 생성형 이미지로 실험하기로 함
- AI 의견: 조건을 정확히 통제할 수 있고(같은 인물로 구도·소매만 바꾸기) 초상권 부담도 없다. 대신 실제 사진보다 깨끗해서 결과가 좋게 나올 수 있으므로, 결론 전에 실제 사진 1장으로 다시 확인한다
- 도구: Higgsfield, GPT Image 2.6 (사용자가 Higgsfield·GPT·Claude 중 질문 → Claude는 사진 생성 불가, 연결된 Higgsfield로 진행)
- 입력 세트(모두 같은 생성 인물, 실제 인물 아님)
  - G1 상반신 · 무지 흰 반팔 · 팔을 몸에서 띄움 (후보 3장 중 사용자가 선택. 팔과 몸통 간격, 손 전체가 보이는 것이 기준)
  - G2 G1 인물의 전신
  - G3 G1 인물이 흰 긴팔을 입은 모습
- 흰 티로 한 이유: 빨간 상품(`red_tee.jpg`)으로 바뀌었는지 색으로 바로 판정할 수 있다

### 준비 중 실수와 해결

- **Issue:** G2·G3를 만들 때 Claude가 "채팅에 올린 순서 = 생성 작업 순서"라고 가정하고 첫 작업을 참조로 넣었다. 결과 인물이 사용자가 고른 G1이 아니라 다른 후보였다. 이대로면 결과 차이가 구도 때문인지 인물 때문인지 구분할 수 없다
- 발견: 결과 4장의 얼굴(앞머리, 옅은 미소)이 고른 G1과 달라서 Claude가 비교 중 발견
- **Improvement:** 작업 ID에 기대지 않고 확정한 G1 파일 자체를 업로드해 참조로 지정한 뒤 다시 생성. 잘못 만든 4장은 기록용으로 따로 보관
- 교훈: 참조 이미지는 순서가 아니라 파일로 지정한다

## 발견

1. **영역은 소매 끝까지 넓게 잡아야 한다.** 몸통만 잡으면 상품의 일부만 바뀐다 (P03)
2. **원본이 긴팔이어도 된다.** 긴소매를 지우고 맨팔을 새로 그려 냈다. 가장 어려울 것으로 예상한 조건이었다 (P04)
3. **팔 이상은 둘 다 seed 42, 오른 팔뚝**에서 생겼다. 영역 아래쪽 모서리에 팔이 걸치는 자리다. 여러 장 생성해서 고르는 구조가 의미 있다
4. 영역 사각형의 경계가 배경에 옅은 사각형으로 남는다 (확대해야 보이는 정도, 전신은 덜 보임)
5. 핏은 상품 사진의 모양을 따라가 몸보다 넓고 박시해진다. "정확한 핏 확인"이 아니라 "입은 모습 미리 보기"로 안내해야 한다
