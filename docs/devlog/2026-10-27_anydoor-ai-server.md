## 1. 생성 속도 진단 (Gradio 데모)

| 회차 | 바꾼 조건 | 시간 | 단계당 | 전용 / 공유 GPU 메모리 |
| --- | --- | --- | --- | --- |
| 1 | 기본 (`save_memory = False`) | 4분 23초 | 8.49초 | (측정 안 함) |
| 2 | 같은 조건 반복 | 4분 11초 | 8.11초 | 9.7GB / **2.4GB** |
| 3 | `save_memory = True` | **2분 10초** | 4.21초 | 9.6~9.7GB / 0.8GB |
| 4 | + 다른 GPU 프로그램 종료 (783MiB → 565MiB) | 2분 25초 | 4.70초 | 9.7GB / 0.6~0.8GB |
| 5 | 같은 조건 반복 | 2분 27초 | 4.75초 | 9.6GB / **2.1GB** |

- **Problem** — 첫 생성 4분 23초. RTX 3080치고도 비정상적으로 느림
- **가설 (AI)** — GPU 메모리(10GB) 부족으로 Windows가 일반 RAM을 GPU 메모리처럼 빌려 씀(공유 GPU 메모리)
- **확인 (직접)** — 작업 관리자: 전용 9.7/10GB 꽉 참 + 공유 2.4GB. 2회차도 4분대 → 첫 실행 문제 아님
- **조치** — 원본 코드에 있던 `save_memory` 켜기 → 2분 10초 (품질 변화 없음). 다른 프로그램 종료는 **효과 없음** → 원인 배제
- **새 위험** — 연속 실행 시 공유 메모리 0.8 → 2.1GB. 생성할수록 느려질 가능성 \[확인 필요\]
- **결정 (사용자)** — 남은 방법(fp16) 대신 **기능 완성 먼저** (D21)

Gradio 실험은 매번 Mask를 손으로 다시 칠했고 Seed도 적용되지 않아(아래 ①), **속도 비교는 유효하지만 품질 비교는 통제된 실험이 아니다.**

## 2. 원본 코드에서 발견한 것 (`run_gradio_demo.py`)

| 발견 | 근거 | 영향 |
| --- | --- | --- |
| ① **Seed가 적용되지 않음** | `seed`를 받기만 하고 쓰지 않음. `np.random`으로 확대·확장 비율을 매번 무작위로 정함 | 같은 Seed인데 결과가 달랐던 진짜 이유. 9/28 PoC의 "Seed 42 고정"도 정정 |
| ② Refine 체크박스 미작동 가능성 | 체크박스 **값**이 아니라 화면 부품 객체를 검사 | "Refine OFF" 기록이 실제와 달랐을 가능성 \[확인 필요\] |
| ③ Shape Control OFF면 Mask를 **감싸는 사각형만** 사용 | `get_bbox_from_mask` → 1.1~1.2배 확장 | DP Editor의 사각형 영역이 그대로 유효함을 코드로 확인 |

처음에 Claude가 "같은 Seed인데 결과가 다른 건 GPU 계산 방식 때문"이라고 설명했는데, 코드를 확인한 뒤 틀린 설명으로 정정했다.

## 3. 구현 — `ai-server/vmd_ai_server.py`

| API | 역할 |
| --- | --- |
| `GET /health` | AI 서버 상태, 생성 중 여부 |
| `POST /generate` | 매장 사진 + 상품 이미지 + x·y·w·h(0~1) → 결과 PNG (헤더에 생성 시간·seed) |

| 설계 결정 | 이유 |
| --- | --- |
| 원본 Gradio 파일은 수정하지 않고 생성 함수만 옮김 | 원본을 불러오면 Gradio 화면까지 켜짐. 잘 돌아가는 원본은 그대로 둠 |
| FastAPI | Gradio 3.39가 이미 설치해 둠 → 추가 설치 없음 |
| Seed를 random·numpy·torch 모두 고정 | 같은 조건 = 같은 결과여야 실험 비교가 의미 있음 |
| 한 번에 한 건만 생성 (중복 요청은 409) | GPU 메모리가 빠듯함 |
| 상품 Mask는 흰 배경 자동 제외 + Refine | VMD Studio에서는 상품 사진에 직접 칠하지 않음 (흰 배경 가정 \[임시\]) |
| 휴대폰 사진 회전 정보(EXIF) 반영 | 화면에 보이는 방향과 좌표 기준을 맞춤 |

## 4. API 첫 생성

영역 값은 DP Editor에서 실제로 지정한 뒤 AI Preview 화면의 생성 조건 값을 옮김: x 0.66 · y 0.23 · w 0.14 · h 0.53

| 회차 | 전체 시간 | 최대 메모리 | 결과 |
| --- | --- | --- | --- |
| A1 | 166.3초 | 9.25GB | 생성 성공 |
| A2 (같은 조건) | 181.3초 | 9.23GB | 눈으로 보기에 동일 (파일 25bytes 차이 → GPU 계산 오차 수준) |

- **성공** — VMD Studio 좌표 → API → 결과 이미지 흐름 완주. 빨간색·반팔 정체성, 행거에 걸린 관계, 매장 조명 자연스러움. Seed 재현성 확인
- **실패 ①** — 영역을 티 한 장으로 줄여도 **원피스처럼 길게 늘어남**
- **실패 ②** — 행거 자리에 라벨 달린 어두운 목 구조 (상품 목 라벨 반영인지 Hallucination인지 미확정)

**원피스 원인 가설 수정** — 처음엔 "Mask가 너무 길다"고 봤지만 영역을 줄여도 같았다. 코드상 AnyDoor는 상품 이미지를 **영역 비율에 맞춰 늘린다** (`cv2.resize(ref_image_collage, (x2 - x1, y2 - y1))`). 정면으로 펼친 넓은 티를 옆으로 걸린 좁고 긴 영역(약 1:3.5)에 끼워 넣은 것으로 보인다 \[검증 전\]. VMD 관점에서는 **상품 사진 방향과 진열 방향의 차이**라는 서비스 설계 질문이 된다.
