# 2026-10-29 | Spring ↔ AnyDoor AI 서버 연결 (PR #9)

## 목표

10/27에 만든 AnyDoor용 Python AI 서버(PR #7)를 VMD Studio(Spring)에 연결해서,
**DP Editor의 [Preview 생성] 버튼 하나로 실제 AnyDoor Preview가 만들어지게** 한다.
계획(10/28~29)에 있던 생성 중 로딩 표시와 AI 서버 꺼짐 안내도 함께 진행한다.

## 1. 구현 — `PreviewGenerator` 구현체 하나 추가

10/01에 Preview 엔진을 `PreviewGenerator` 인터페이스로 분리해 두었다(D9). 그래서 이번 연결은
**TaskService·화면·API를 고치지 않고 구현체 하나를 추가하는 것**으로 끝났다.

| 추가·변경 | 역할 |
| --- | --- |
| `AnyDoorPreviewGenerator` | 매장 사진·상품 이미지·영역(0~1)을 AI 서버 `POST /generate`로 보내고, 결과 PNG를 `uploads/preview-*.png`로 저장한 뒤 주소를 돌려줌 |
| `vmd.preview.engine=anydoor` / `mock` | 설정 한 줄로 엔진 전환. Mock은 GPU가 없는 노트북에서 화면 흐름을 시연하기 위해 남김 |
| `GET /api/previews/{파일}` | 생성 결과 이미지 제공. `preview-UUID.png` 모양만 허용해 다른 업로드 파일은 꺼낼 수 없게 함 |
| DP Editor | 버튼에 경과 시간 표시(`Preview 생성 중... 1:23`), 생성 중 영역 수정·재클릭 잠금 |

| 설계 결정 | 이유 |
| --- | --- |
| 연결 대기 3초 / 응답 대기 5분 | 서버가 꺼져 있으면 바로 안내하고, 2~3분 걸리는 생성은 끝까지 기다림 |
| 오류를 상황별로 나눠 안내 | 꺼짐 503, 다른 생성 중 409, 시간 초과 504, 그 외에는 AI 서버의 안내 문구를 그대로 표시 |
| 생성 파라미터(strength·steps·scale·seed)는 AI 서버 기본값 사용 | PoC 기준 설정과 Seed 42를 한 곳(AI 서버)에서만 관리 |

## 2. 학교 PC 실행 확인

| 확인 | 결과 |
| --- | --- |
| 정상 생성 | Spring 로그 152.7초, AI 서버 로그 150.2초, `seed=42`, `POST /generate 200 OK` |
| AI 서버 꺼짐 | 약 1초 만에 "AI Preview 서버에 연결할 수 없습니다…" 안내 |
| 같은 조건 재생성 | 결과 이미지가 눈으로 보기에 동일 (10/31 픽셀 비교: 최대 차 2/255) → Spring을 거쳐도 Seed 재현성 유지 |

- Spring과 AI 서버의 시간 차이는 약 2.5초(이미지 전송·상품 Mask 다듬기·저장). 병목은 여전히 AnyDoor 생성 자체 → D21 판단 유지
- 최대 GPU 메모리 9.25GB / 10GB (92%). 다른 GPU 프로그램이 겹치면 메모리 부족(503)이 날 수 있음 → 시연 전 주의

Java 빌드는 Claude 환경에서 Gradle 다운로드가 막혀 확인하지 못했고, 학교 PC IntelliJ 실행으로 확인했다. 화면 동작(생성 중 잠금, 실패 시 복구, 성공 시 이동)은 Claude가 jsdom 시뮬레이션으로 먼저 확인했다.

## 3. 연결 후 발견한 문제 2개

연결 성공 화면을 로그와 대조하다가, **Mock 단계에 맞춰 둔 문구와 규칙이 엔진을 바꾼 뒤에도 남아 있는 것**을 발견했다.

| 문제 | 원인 | 수정 |
| --- | --- | --- |
| ① 실제 AnyDoor 결과인데 화면에 "현재 Mock 단계 … (AnyDoor 연동 전)" 문구와 MOCK 표시 | Mock만 있던 시절에 HTML에 고정해 둔 글자 | 결과 주소로 엔진을 구분해 **ANYDOOR / MOCK** 표시와 안내 문구를 바꿈. AnyDoor 결과에는 "길이·그래픽·디테일은 실제와 다를 수 있으니 실제 상품 이미지를 기준으로" 안내 |
| ② 검토 완료 상태에서 Preview를 다시 만들어도 검토 완료 유지 → 새 Preview를 채택하면 [작성 완료] 없이 공유 가능 | Mock은 항상 같은 이미지라 드러나지 않았음. AnyDoor로 같은 영역을 재생성할 수 있게 되면서 생긴 경우 | Preview를 새로 만들면 검토 완료 → 작업 중 (D14 "검토 완료는 현재 채택안 기준"을 재생성까지 확장) |

- 발견: Claude가 사용자가 보낸 캡처(상단 "검토 완료" 상태, Mock 문구)에서 발견해 수정
- 확인: 사용자가 학교 PC에서 직접 확인 (ANYDOOR 표시, 같은 영역 재생성 후 "작업 중"으로 변경) 후 병합
- 의미: 인터페이스로 엔진만 바꿔도, **이전 단계의 가정은 다른 곳에 숨어 남아 있다**

## 4. 결과 이미지 관찰

- 영역: 10/27과 같은 흰 티 한 장 너비의 좁고 긴 영역 (x 0.66 · y 0.23 · w 0.14 · h 0.53), Seed 42
- **성공** — 행거에 걸린 관계, 매장 조명은 자연스러움
- **실패** — 빨간 반팔 티가 이번에도 **원피스처럼 길게** 늘어남. 같은 조건·같은 Seed라 10/27 결과가 재현된 것
- 해석: "상품 이미지가 영역 비율에 맞춰 늘어난다"는 가설과 맞는 관찰이 하나 더 쌓였을 뿐, 원인은 아직 **검증 전**. 영역 비율만 바꾸는 통제 실험이 필요
